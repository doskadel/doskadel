## B1. Токен не рефрешится — ЗАКРЫТ 2026-10-03 (access+refresh, cookie, reuse-detection)

_(историческое описание ниже)_
**Симптом:** через ~сутки после регистрации/входа запросы падают, ответ `{"success":false,"message":"Invalid credentials"}`.
**Причина (факт):** `backend/src/controllers/authController.js` — `jwt.sign(..., { expiresIn: '24h' })`. Refresh-механизма НЕТ: ни `/api/auth/refresh`, ни refresh-токена, ни соответствующей логики на фронте. Через 24 ч токен мёртв.
**Дополнительно:** при 401 фронт, видимо, не разлогинивает корректно, а показывает ошибку логина (путает с неверным паролем).
**Что нужно:** refresh-токен (долгоживущий) + короткий access-токен; endpoint `/api/auth/refresh`; на фронте — автообновление при 401 и корректный логаут при неудаче.
**Приоритет:** высокий (ломает базовый сценарий).
**Решение:** см. QUESTIONS Q7 (схема auth).

## B8. Календарь: pending-вхождения гасили маркеры — ЗАКРЫТ 2026-10-05 (aad1fde)

**Симптом:** маркеры повторяющихся задач в календаре пропадали после того, как push-job материализовал Occurrence.
**Причина:** в computeOccurrences блок `if (ex)` делал `continue` для любого существующего Occurrence, включая `pending` без переноса — вхождения гасились.
**Решение:** pending без переноса отдаётся как обычное вхождение; continue только для done/skipped/missed. Проверено: 0 → 11.

## B7. Календарь: вхождения раньше создания задачи — ЗАКРЫТ 2026-10-05 (406e6aa)

**Симптом:** у повторяющихся задач в календаре видны маркеры на датах до их создания.
**Причина:** computeOccurrences не учитывал createdAt как нижнюю границу (floorDays=0 для календаря).
**Решение:** нижняя граница = max(createdAt, startDate, activeSince). Тест: до createdAt 0 вхождений, после — есть.
