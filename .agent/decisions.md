### Позиционирование (решение оператора + совет Клода)

### workspaceId — через единый слой доступа (ответ Q5)
- **Модели пока не менять.** Поле `workspaceId` в User (personal workspace) + коллекция Workspace {_id, ownerId}.
- **Ключевое:** все запросы к данным пропустить через **единый слой** (репозиторий/хелпер), где сейчас фильтр `userId`. Тогда переход на workspaceId = правка в одном месте + скрипт миграции, а не по всему коду.
- Вариант Б (workspaceId во все модели сейчас) — преждевременен.

### Auth: cookie-схема (ответ Q4)
- **Один домен + reverse-proxy** (nginx/Caddy в Docker): `/` -> фронт, `/api` -> бэк. Cookie first-party, CORS не нужен.
- Cookie: **httpOnly, Secure, SameSite=Lax** (Strict допустим), `Path=/api/auth/refresh`.
- **В dev так же:** прокси CRA/Vite `/api` на бэк (порты 3000/5000 не мешают).
- **SameSite=None — НЕ брать** (усложняет CORS, ослабляет CSRF).
- **localStorage для refresh — НЕЛЬЗЯ** (XSS крадёт на 30 дней; reuse-detection не лечит).
- **Проверка Origin на refresh/logout** — дешёвая CSRF-защита.
- Access (15м) — держать **в памяти JS**, после перезагрузки получать заново через refresh.

### Бот-ассистент (ответ Q6)
- **LLM в проде — на сервере**, не на клиенте (ключ нельзя отдавать в SPA). Дев-инструменты (DeepSeek-чат, userscript) к продукту не относятся.
- Провайдер **сменный через один адаптер** и env-ключ; rate limit на пользователя. Бесплатный tier (Ollama Cloud/Groq/Gemini) для старта ок, без SLA. Локальная Ollama (8 ГБ) — только для дева.
- **Изменения данных:** LLM НЕ пишет в БД, а возвращает структурированное **намерение** (search_tasks, update_task с id и полями). Сервер валидирует схемой, проверяет владельца (`userId` из токена, НЕ из ответа LLM); для изменений/удалений — **превью-diff с подтверждением**; поиск/чтение без подтверждения.
- **Prompt injection:** текст задач/статей в промпте — недоверенный; действия только по запросу пользователя, не по инструкциям из данных.
- **RAG на бэке:** для сотен-тысяч записей хватит **Mongo text index**, эмбеддинги не нужны на старте. Фильтр по userId/workspaceId — всегда до подачи в LLM.
