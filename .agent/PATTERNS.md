## Правки файлов (после инцидента 2026-10-04)

**Правило:** правки только через `edit_file` (точечно, с уникальным контекстом).

**Запрещено:** python-однострочники вида `open(p,'w').write(open(p).read()...)` — `open(w)` усекает файл ДО чтения, файл стирается. Дважды потеряли файлы (TaskController, recurrence.js и др.); восстановили из git, часть правок переписали вручную.

**Перед правкой моделей/критичных файлов:** `git status` должен быть чистым; если есть незакоммиченные правки — сначала коммит (wip-коммиты не стыдно, мелкие и частые).

**Массовая замена:** если нужно заменить в многих файлах — по одному через `edit_file`, либо отдельным скриптом, который ГАРАНТИРОВАННО читает до записи (сначала `s = read(f)`, потом `write(f, s.replace(...))`, в разных инструкциях).

## Тесты
- Тестовые скрипты должны чистить за собой ВСЕ коллекции (включая Status), иначе копится мусор. При падении — авто-очистка старых тестовых пользователей в начале прогона (см. test-isolation.js).
- Перед боевой миграцией — mongodump. Миграции идемпотентны, dry-run со счётчиками.
