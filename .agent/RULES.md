# RULES: DoskaDel — регламент работы над проектом

Согласовано с оператором 2026-10-02. Дополняет docs/ROLES.md ядра (проектная специфика).

## Как ставится работа
1. **Оператор формулирует задачу** (что сделать).
2. **DeepSeek (ярус 2) реализует до конца, самостоятельно.** Не задавать оператору вопросы, на которые он «полдня будет думать, потому что не шарит». Если решение в моей компетенции — принимать сам.
3. **Клод (ярус 1)** — только сложное/архитектурное/спорное. К нему идут через контрольные точки (merge в main при сомнении, смена архитектуры, 2 упавших прогона, спорное решение).
4. **Оператор проверяет готовую фичу** — руками. Итог: либо возвращает с багами, либо принимает и пушим на прод.

## Git и деплой
- **Ветки:** работа в `wip/...`.
- **Merge и push в main:** DeepSeek и Claude могут **сами** (оператор разрешил 2026-10-02). Обоснование: git позволяет откатиться. После merge — сообщить оператору.
- **Деплой на прод-сервер:** только с **явного апрува оператора**. Автоматически на сервер не заливать.

## Что можно без Клода (рутина яруса 2)
Переименования, багфиксы с ясной причиной, UI/UX-правки в рамках утверждённого видения, рефакторинг, тесты, документация. Всё, где нет архитектурной развилки.

## Что только с Клодом (ярус 1)
Позиционирование, схема auth, архитектура бота, смена стека, крупные решения о структуре данных. Вопросы копятся в QUESTIONS.md, отправляются пакетом.

## Несохранённые данные (правило, 2026-10-03)
Везде, где есть создание/редактирование с кнопкой сохранения, выход без сохранения (X, клик по фону, Esc, «Назад», смена экрана) показывает **confirm-диалог** — но **только если есть реальные изменения** (сравнение со снимком, `isDirty`). Используется `useConfirm`: title «Есть несохранённые данные», message «Изменения будут потеряны. Закрыть форму?», confirmLabel «Закрыть», danger true. После подтверждения — откат к снимку.
Покрыто: ProfileModal (notifications), Dashboard (настройки), StatusManager (формы), TaskModal/ArticleModal (через useTaskDetail/useArticleDetail), TaskDetail/ArticleDetail, SearchModal. Создание задачи/статьи (Tasks/Knowledge) — было.

## Приёмка
- Фича считается готовой, когда: код в ветке, тесты зелёные (если применимо), я сообщил оператору что проверять и как.
- Оператор тестирует на своём окружении. Возврат с багами — нормальный цикл, не ошибка.
